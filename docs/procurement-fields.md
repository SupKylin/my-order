# 采购字段、风险地址与筛选导出

## 采购渠道折扣与结算成本

- 采购渠道新增/编辑弹框分别维护 FBA、FBM 两套采购渠道汇率、当前实时汇率、税金，最多两位小数；当前实时汇率须大于0，其余为非负数字。每套三个值全部留空表示该模式未配置，不能只填一部分。税金直接作为乘数：1.08表示乘1.08，8表示乘8，不自动换算百分比。
- 采购折扣 = 采购渠道汇率 ÷ 当前实时汇率 × 税金，四舍五入保留4位小数；弹框展示公式及结果。采购成本 = 结算时保存的采购折扣 × 采购金额，四舍五入保留2位。前后端使用整数十进制计算，避免金额浮点误差；无新增组件或依赖。
- 订单由非已结算切换到“已结算”时，须有发货模式 FBA 或 FBM，按该模式取折扣（不是平台履约方 WFS）。单个采购渠道自动使用，多渠道须选择一个“成本计算渠道”，且须属于该订单已分配渠道、已启用并已配置对应模式折扣。采购金额须为有效非负数字；缺少条件提示错误，不保存本次修改。
- 结算时保存成本计算渠道名称、折扣及成本。渠道随后调价、改名、停用或订单重新分配采购渠道，不会改写原结算快照；修改已结算订单采购金额时按已存折扣重算。主动修改成本计算渠道或发货模式时按对应渠道及模式的当前折扣重算；已结算时不能清空发货模式。改回未结算/清空结算情况时清除折扣和成本，重新结算按当时配置计算。
- 没有历史成本快照的已结算订单继续保持折扣和成本空值，不推测历史汇率；已有快照保留。普通编辑、金额导入或重复导入“已结算”不会自动补填历史成本；可重新结算或明确选择成本计算渠道后计算。
- 列表、按账号表头设置及完整订单导出包含成本计算渠道、采购折扣和采购成本。折扣/成本只读，不能通过编辑或Excel覆盖；导入模板可映射成本计算渠道（填写已分配渠道全名）、采购金额和结算情况，和编辑共用计算规则。导入预览检查配置和金额，多行同一明细按文件顺序模拟；提交再次校验，发生错误整批回滚。WFS只读、账号店铺范围、采购状态及渠道分配权限保持原规则。
- 升级时原采购渠道配置仅一次性复制到 FBA、FBM 两套，使用初始化标记保证后续调整或清空不被重复迁移覆盖；原字段保留。已有订单的折扣、采购成本保持原值，不推测补填。Walmart重复同步不修改采购成本。发布须运行标准数据库增量迁移，不清理业务数据。

## 手工佣金与订单利润

2026-11-09 参考配置展示已发布至 `20261109040443235-d4155e`；仅调整未结算详情的显示来源，结算快照及利润计算口径不变。

- 店铺管理新增佣金（%），人工填写0至100、最多2位小数，15代表15%；允许留空，旧店铺初始为空。不调用 Walmart 拉取佣金。
- 订单从非已结算变为“已结算”时，将店铺当前佣金复制到采购记录的 `commissionRate`，即结算费率。费率为空也可结算，但利润显示未计算；缺失不作0。修改店铺佣金只影响之后结算的订单。
- 已结算订单重复导入、修改金额、成本渠道或 FBA／FBM 模式，均保留原结算费率。离开已结算状态清除该快照；重新结算取当时店铺费率。历史已结算订单没有快照时保持空值，不通过普通编辑或重复导入补填。
- 未结算订单的展开详情和编辑抽屉展示当前店铺佣金及当前采购渠道对应 FBA／FBM 折扣，标注“当前配置，结算时确定”；采购金额为空也可查看参考配置。单渠道自动参考，多渠道须明确成本计算渠道；未分配、未选模式、渠道未启用或配置缺失时显示原因，不猜测费率。编辑打开时重读渠道配置，模式/渠道草稿变化同步更新参考折扣。已结算继续展示历史快照，历史空值不回退当前配置；参考值不落库，不参与未结算成本/利润计算或导出/周月汇总。订单读取仅在原店铺关联中增加当前佣金属性，无额外逐条查询、迁移或依赖。
- 每条未取消、已结算且金额、结算佣金、成本及应填退款金额齐全的商品明细：佣金金额＝订单金额×结算佣金率÷100，保留2位；利润＝订单金额－佣金金额－采购成本－卖家退款净扣款＋采购退款金额＋争议成功金额，保留2位，允许负利润及0费率。不额外扣除公式外费用，不属于实际到账净利润。
- Walmart退款金额（卖家净扣款）：只使用已完整下载并按店铺、客户订单号、SKU及PO准确关联的官方Recon交易Refund贷借明细，包含税款代扣及佣金返还等费用项，不混入Dispute Settlement。无已退款记录按0计算；已退款但官方净额缺失、覆盖不完整或有冲突时显示缺失提示，暂不计算利润；官方有效0正常显示。字段只读，四角色均不能手改或清空，Excel不能覆盖，不展示客户含税退款或独立来源字段。
- 采购退款金额直接读取关联采购售后工单已保存金额，处理中保存后也立即计入利润；无工单显示“—”、按0计算，有工单但金额未填写则提示并暂不计算利润。0元是有效金额。工单保存不回写订单成本或采购记录，查询时读取最新金额。
- 争议成功金额仅通过订单编辑手工维护，非负、最多12位整数和2位小数，允许0及清空，未填写按0计算。四角色沿用订单访问权限，WFS仍只读；保存沿用版本冲突保护和操作日志。Excel不能导入，模板不提供映射，旧映射和旧预览提交均忽略并提示。
- 订单列表、表头设置、展开详情及完整导出仅展示一个“Walmart退款金额”，该值统一为卖家退款净扣款，并直接用于利润计算；不展示客户退款接口含税金额或单独的净额来源列。编辑页同一个退款字段仅只读展示官方净扣款。退货状态详情保留时间、数量和状态，不显示与净扣款不同口径的原始含税金额。Walmart退款金额由接口维护，争议成功金额仍仅手工维护，均禁止Excel导入；沿用店铺权限、WFS只读与审计日志。
- 两项退款、佣金金额、利润均由系统读取或计算，不能手改或通过Excel覆盖；采购填写模板布局不变。订单、退款或工单金额变化后，列表刷新、重新打开详情及店铺统计查询使用新金额，仍保留原结算费率和成本快照，Walmart同步不覆盖争议金额。
- 本次在 `purchases` 增量添加可空 `disputeSuccessAmount DECIMAL(18,2)`，历史留空，不回填或修改原金额；原店铺/采购佣金迁移保持不变。利润查询时计算，复用现有退款同步，不增加依赖、独立采集任务或逐条Walmart请求。周/月统计见 [首页统计](home-dashboard.md)。验证使用 `purchase-cost-integration.test.js` 的 `my_order_cost_test_数字` 隔离库及 `order-profit.test.js`。

## 商品数量与采购数量

原 `quantity` 字段改名展示为“商品数量”，仍保存 Walmart 商品行的售出数量，只读、不可采购导入。新增采购字段 `purchaseQuantity`（“采购数量”），新订单首次入库时初始化为商品数量；历史订单保持 NULL，不回填。重复同步即使改变商品数量，也不覆盖采购数量或补齐空值。

采购数量支持页面编辑和 Excel 映射导入，沿用数量的 1 至 1000000 正整数校验；页面允许清空，导入空白保留原值。WFS 只读、运营店铺权限和并发冲突校验同时生效。列表默认提供两列，可分别参与账号表头设置；完整订单导出和采购填写模板均保留两列。旧“数量”表头仍识别为只读商品数量，不自动改为采购数量。

增量迁移只新增 `purchases.purchaseQuantity` 可空整数列，无回填、无新增索引或依赖。升级后需重新生成旧采购预览，以使用包含采购数量的并发摘要。

## 列表筛选与表头设置

- “更多筛选”新增平台到货日期区间，对应 `platformDeliveryDate`，包含开始日与结束日；沿用平台发货日期的日期口径，不另做时区转换。选择只修改草稿，点击查询后生效；翻页、刷新、预警统计和两类导出复用已查询条件，清空后查询或重置解除限制。接口参数为 `deliveryStartDate`、`deliveryEndDate`，支持单边范围，非法日期或开始晚于结束时拒绝查询。
- 采购渠道、采购状态、运营订单状态、未出跟踪号、价格系数等级支持多选：同框内任一匹配，框间同时满足；清空表示不限。未出跟踪号选中“全部”时覆盖其他提醒等级，但仍只筛选未出跟踪号订单。选项点击后仅更新草稿，查询、翻页及两种导出使用已应用条件。
- 采购状态筛选新增“未填写（空值）”，匹配 NULL、空字符串和纯空白，可与实际采购状态同时多选取并集，再与渠道等其他条件取交集；不新增字典值或修改订单。列表与两类导出使用相同规则。

- 店铺筛选来自店铺管理；“店铺所属账号”按店铺绑定账号筛选。运营范围始终限制为本人所属店铺，筛选不能扩大权限。
- 采购渠道支持多选分配，以本次选择覆盖原渠道；渠道筛选也支持多选，可同时选择实际渠道与“未分配”，取并集。空值入口和同名的真实“未分配”渠道独立；兼容历史单选文本与多选数组。采购人员不再是列表分配对象。
- 采购状态修改和采购渠道分配（含批量）仅管理员、采购可操作；运营的编辑字段只读、操作按钮隐藏，后端拒绝修改或清空，仍可查看、筛选和导出。运营导入忽略采购状态并提示，不影响其他有效字段；采购渠道继续不通过导入更新。
- “更多筛选”中的发货模式使用系统字段选项 FBM、FBA，点击查询后生效，清空后查询或重置后不限制模式；与履约方是两个独立条件。
- “更多筛选”中的采购平台支持多选，选项来自采购平台维护的启用项；匹配任一所选平台，清空或重置后不限制平台。列表、预警统计及两类导出使用同一条件。
- 履约方、平台订单状态、运营订单状态等可组合查询。“主管确认”字段已停用，列表、表头设置、编辑、筛选及导出均不再提供该字段；旧数据库列和值保留，不清库或删列。
- 价格区间支持采购商品链接金额、订单金额和采购限价，包含上下边界；可只填一端，两端为空则不限制。
- 采购限价由系统按“采购商品链接金额 × 1.1”计算并保留 2 位小数；价格系数按“（订单金额 × 0.85）÷（采购商品链接金额 + 税费）”计算并保留 4 位小数。采购商品链接金额、订单金额或税费无效，或分母小于等于 0 时，两字段留空；空税费按 0 计算。编辑和采购导入不能手工覆盖这两个字段，旧模板中的映射会被跳过并提示。价格系数小于 0.8 标为“低”，0.8（含）至 0.85（不含）为“平”，0.85 及以上为“高”；空值或非数字不标记。等级支持筛选，标记不写入订单号。
- 筛选在数据库分页前执行，总数、预警统计及两类导出使用相同条件与权限。导出覆盖全部匹配记录，不只导出当前页。
- 修改筛选、输入关键词或点击“只看我的店铺”只修改草稿，点击“查询”才应用。首次进入、翻页、调整每页条数和刷新仍加载数据，翻页、刷新及导出沿用上次已查询的条件；切回浏览器标签页不自动请求。重置清空并重新查询。
- 多选按商品明细 ID 跨页保留，可跨页批量分配渠道、修改采购状态或运营订单状态、复制物流单号；重新查询、重置、刷新或操作成功后清空，避免误操作旧结果。WFS 不可勾选，批量操作仍由后端校验权限、版本和数量上限。
- 顶部及勾选操作条提供“批量更改采购状态”，弹窗读取当前启用的采购状态选项，确认后更新所选 1 至 500 条明细。成功时间遵循单条编辑与导入的同一规则；任一无权限、WFS、版本冲突或记录缺失均整批回滚，变更自动记录操作日志。提交期间显示加载态，防止重复提交。本功能不新增数据库列或依赖。
- 批量采购状态及渠道组合筛选验证：`backend/test/purchase-batch-status-integration.test.js` 使用 `my_order_batch_status_test_数字时间戳` 临时库，覆盖成功时间、整批回滚、权限、日志、实际接口、分页与两类导出一致性。
- 顶部及勾选操作条新增“批量修改跟单备注”，对跨页勾选的 1 至 500 条明细支持覆盖、追加 `followupNote`，或明确选择“清空备注”后置空。追加保留每条明细的原备注，换行后追加本次内容；原备注为空或纯空白则直接写入。追加后的总长度不得超过 12000 字符，任一明细超限则整批不修改并提示。空白输入不能隐式清空，弹窗展示影响条数，备注沿用 12000 字符上限。管理员、采购可修改全部可编辑订单，运营仅本人店铺；WFS、版本冲突、越权或缺失记录均整批回滚。提交显示 loading、防重复点击，失败保留草稿；成功刷新并清空勾选。事务记录操作摘要及字段前后值，不更改采购状态、成功时间或其他采购字段；无需数据库迁移或新增依赖。
- 列名统一为“采购状态”。采购成功时间、采购分配时间在列表和完整导出中仅显示北京时间日期（YYYY-MM-DD）；后台保留精确时间用于小时提醒与时间区间筛选。
- 表头设置支持勾选显示列、拖动手柄排序；靠近列表边缘时自动滚动。店铺名、订单号保持固定左侧，不参与拖动。保存后写入当前账号的 `orderTablePreferences`，刷新、重新登录和换电脑可恢复；取消不保存，保存失败保留草稿以便重试。
- 首次没有服务端配置时兼容同账号的旧浏览器勾选设置，保存后以数据库为准。列设置不改变任何订单数据，也不改变两类导出的固定列顺序。

## 审核与供应商分配状态

订单列表新增“审核状态”（`reviewStatus`）和“分配供应商状态”（`supplierAssignmentStatus`），可筛选、参与表头显示/拖动设置及完整订单导出。两字段由系统维护，不能人工编辑或映射导入；采购填写模板不包含这两个字段。

| 是否可分配 | 采购渠道 | 审核状态          | 分配供应商状态    |
| ---------- | -------- | ----------------- | ----------------- |
| 空值       | 任意     | 未审核（存 NULL） | 未分配（存 NULL） |
| 是         | 空值     | 已审核            | 未分配（存 NULL） |
| 是         | 有值     | 已审核            | 已分配            |
| 否         | 任意     | 不可分配          | 不可分配          |

编辑或采购导入变更是否可分配、编辑或分配操作变更采购渠道时，在同一事务中重新计算两状态。是否可分配为空或否时禁止新增、替换采购渠道，后端同时校验单条、批量及直接编辑请求；任一批量目标不满足条件则整批回滚。允许清空渠道，也允许将是否可分配清空。清空是否可分配或改为否不会删除已有渠道，保留记录供核对，但显示状态按上表处理。

采购导入空白单元格继续保留原值；需要清空是否可分配时使用编辑页面。WFS 人工只读和运营店铺权限继续生效，筛选不能扩大权限，两类导出与列表使用相同状态筛选。

Walmart 新建订单的是否可分配、采购渠道及两个新状态均为空；重复同步不清空人工数据。增量迁移添加两个可空列，每批 500 条按历史是否可分配和采购渠道回填状态，不改原采购值；可重复执行。部署前必须执行统一的 `npm run db:migrate`，不需要 Redis 或消息队列。

## 采购分配时间

`purchaseAssignedAt` 为系统自动记录的采购分配时间。单条分配、批量分配或编辑使采购渠道实际变化时，在同一事务内更新为服务器当前时间，清空渠道也记录；重复保存相同渠道或仅改变多选顺序不更新时间。仅修改是否可分配、采购导入及 Walmart 重复同步不重置此时间。该字段不能手工修改或映射导入。

历史数据保持空值，不根据旧采购人员分配时间推测回填。订单列表在采购渠道后显示该列，可通过表头设置排序和隐藏，完整订单导出包含该列。采购分配日期使用与平台发货日期一致的区间选择框，按北京时间开始日 00:00:00 至结束日 23:59:59（包含该秒全部毫秒）筛选；选择后点击查询才生效，清空或重置解除日期限制。列表、统计及两类导出共用条件和权限，采购填写模板列不变。

增量迁移仅增加可空 `DATETIME(3)` 字段及时间筛选索引，可重复执行；不需要新增缓存或队列。

订单列表底部展示“今日分配”渠道汇总，替代原订单来源说明。按北京时间当天最新采购分配时间和当前采购渠道统计商品明细，多选渠道各计一条；不按订单号去重，不累计历史分配操作，改分归入新渠道、清空不计入。历史分配时间为空的明细不计入。

统计独立于列表筛选和分页，但遵守运营所属店铺权限。随列表查询、翻页、刷新及分配完成后的刷新更新，不额外轮询；北京时间午夜自动隐藏昨日数字，新查询返回当天数据，不删除任何业务记录。数据库使用分配时间范围及现有索引先聚合渠道组合，只返回渠道计数，不下载全部订单。

## 采购成功时间与跟踪号提醒

`purchaseConfirmedAt` 为自动生成的采购成功时间，订单列表和完整订单导出可显示；不可人工编辑，也不可通过 Excel 映射导入。服务器在实际保存采购状态时应用以下规则，上传或预览不触发：

| 状态变化                                                       | 采购成功时间       |
| -------------------------------------------------------------- | ------------------ |
| 空值或其他非成功状态 → 采购成功未出跟踪号 / 采购成功已出跟踪号 | 记录当前服务器时间 |
| 两个成功状态之间切换，或重复保存同一成功状态                   | 保留原时间         |
| 成功状态 → 采购中、采购失败、取消订单、砍单等非成功状态        | 清空               |
| 未提供采购状态，或无效采购状态被导入跳过                       | 不改变             |

成功状态识别兼容空格及中英文括号。“采购成功（砍单）”属于非成功状态。普通编辑和采购导入共用规则；若成功状态历史记录原时间为空，成功状态之间切换也不会凭空补一个时间。

未出跟踪号提醒按服务器时间连续计时，包含夜间和周末：不足 24 小时普通提醒，24 至不足 48 小时黄色，满 48 小时红色“强制处理”。填写物流单号隐藏提醒，删除后按原采购成功时间继续计算；关闭页面或重启服务不重置。

增量迁移为缺少该字段的表添加可空列，并仅为已有“采购成功未出跟踪号”且时间为空的记录以迁移时刻补齐，不倒推历史、不覆盖已有时间。

## 编辑与同步并发

编辑表单只提交实际修改的可编辑字段及打开时的原值。服务器在事务内比较这些字段的最新值：后台同步或其他账号只修改了无关字段时可以保存；同一字段已变化时返回具体字段名称并保留表单内容，不能自动覆盖。手工清空仍显式提交 NULL。未携带字段原值的旧客户端继续按整条记录版本校验。

Walmart 重复拉取相同业务值不增加订单版本；实际平台字段变化仍增加版本，以兼容旧客户端。商品快照抓取时间等内部信息不参与人工冲突判断。采购导入使用预览采购摘要校验，详见[采购导入](purchase-import.md)。该优化不新增数据库字段、依赖或队列。

## 升级

先执行 `npm run db:migrate`，再启动新版后端。迁移只新增表、字段和索引，不清空订单、采购或店铺数据。已有订单的地址指纹分批补齐；金额及履约方从保存的 Walmart 原始响应回填，缺少原始响应时保留原值，等待下次官方同步。回填不请求远端接口，也不触发订单确认。
