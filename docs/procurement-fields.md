# 采购字段、风险地址与筛选导出

- 采购平台为单选，初始选项 Amazon、Ebay；在“采购平台维护”新增、改名、排序或停用。历史订单保留旧名称。
- 发货模式为 FBM/FBA；售后结果当前为“已结束”；售后结果截图沿用本地图片上传、缩略图和放大预览。
- “是否可分配”的“未分配”仅为筛选选项，匹配 NULL 或空字符串，不改变业务字段“是/否”的含义。
- 订单金额合计当前 Walmart 商品行 charges 中 PRODUCT 与 SHIPPING 的 chargeAmount.amount，不包含税费、不再乘数量。履约方直接保存订单 shipNode.type 原值，不与采购发货模式混用。
- 风险地址按地址一、地址二、城市、州、邮编匹配，忽略大小写、首尾空格和连续空白差异；保留房号、标点和邮编格式。地址一、城市、州、邮编必填。新增、编辑、删除地址立即影响新旧订单下次查询的风险标记；订单地址编辑和 API 同步更新地址指纹。备注可在订单风险标签悬停查看。
- “导出订单”和“导出数据填写采购信息”均使用当前筛选条件，导出所有匹配页，不受勾选行和当前页影响。空结果提示无可导出订单。
- 采购填写模板按截图顺序导出 13 列；店铺名、订单号、WalmartSku、数量以及现有采购值填入表格。订单号、SKU 和金额保持文本精度。填好后在“导入采购”通过模板映射更新已有订单，数量仅供参考，不参与采购信息更新。发货方式表头自动建议映射到发货模式。

## 升级

先执行 `npm run db:migrate`，再启动新版后端。迁移只新增表、字段和索引，不清空订单、采购或店铺数据。已有订单的地址指纹分批补齐；金额及履约方从保存的 Walmart 原始响应回填，缺少原始响应时保留原值，等待下次官方同步。回填不请求远端接口，也不触发订单确认。

## 验证

`backend/test/procurement-fields-integration.test.js` 需通过 `DB_NAME=my_order_procurement_test_<数字>` 指定临时数据库后执行；自动创建和清理该测试库，绝不清理业务库。覆盖风险地址维护、新采购字段、筛选导出、填写模板导入及迁移回填。
