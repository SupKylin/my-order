# 采购字段、风险地址与筛选导出

- 采购平台为单选，初始选项 Amazon、Ebay；在“采购平台维护”新增、改名、排序或停用。历史订单保留旧名称。
- 发货模式为 FBM/FBA；售后结果当前为“已结束”；售后结果截图沿用本地图片上传、缩略图和放大预览。
- “是否可分配”的“未分配”仅为筛选选项，匹配 NULL 或空字符串，不改变业务字段“是/否”的含义。
- 订单金额合计当前 Walmart 商品行 charges 中 PRODUCT 与 SHIPPING 的 chargeAmount.amount，不包含税费、不再乘数量。履约方直接保存订单 shipNode.type 原值，不与采购发货模式混用。
- 风险地址按地址一、地址二、城市、州、邮编匹配，忽略大小写、首尾空格和连续空白差异；保留房号、标点和邮编格式。地址一、城市、州、邮编必填。新增、编辑、删除地址立即影响新旧订单下次查询的风险标记；API 同步地址时更新地址指纹，收件信息不能人工修改。备注可在订单风险标签悬停查看。
- “导出订单”和“导出数据填写采购信息”均使用当前筛选条件，导出所有匹配页，不受勾选行和当前页影响。空结果提示无可导出订单。
- 采购填写模板导出 14 列，依次为：店铺名、订单号、WalmartSku、数量、采购商品链接、采购Sku、采购商品链接金额、采购平台、发货方式（FBA/FBM）、采购商家名、采购限价、是否可分配、不可分配原因、运营备注。填入已有值，订单号、SKU 和金额保持文本精度。数量及运营备注仅供参考，采购导入不回写；发货方式表头自动建议映射到发货模式。
- 采购填写模板中的采购平台、发货模式、是否可分配单元格提供 Excel 下拉选项，取导出时系统启用的选项，允许留空。选项保存在隐藏工作表及命名区域中；下载后的文件不会随系统字典变化自动刷新，需要重新导出。
- 完整订单导出在商品图片列嵌入 96×96 缩略图，可点击查看官方原图；图片下载失败时显示原图链接。采购填写模板不含图片列。导出缓存、并发下载和进度说明见[发布文档](docker-release.md)。

## 列表筛选与表头设置

- 店铺筛选来自店铺管理；“店铺所属账号”按店铺绑定账号筛选。运营范围始终限制为本人所属店铺，筛选不能扩大权限。
- 采购渠道支持多选分配，以本次选择覆盖原渠道；“未分配”筛选无渠道数据。采购人员不再是列表分配对象。
- “更多筛选”中的发货模式使用系统字段选项 FBM、FBA，点击查询后生效，清空后查询或重置后不限制模式；与履约方是两个独立条件。
- “更多筛选”中的采购平台支持多选，选项来自采购平台维护的启用项；匹配任一所选平台，清空或重置后不限制平台。列表、预警统计及两类导出使用同一条件。
- 履约方、平台订单状态、运营订单状态等可组合查询。“主管确认”字段已停用，列表、表头设置、编辑、筛选及导出均不再提供该字段；旧数据库列和值保留，不清库或删列。
- 价格区间支持采购商品链接金额、订单金额和采购限价，包含上下边界；可只填一端，两端为空则不限制。
- 价格系数及采购限价人工填写，不自动计算。价格系数小于 0.8 标为“低”，0.8（含）至 0.85（不含）为“平”，0.85 及以上为“高”；空值或非数字不标记。等级支持筛选，标记不写入订单号。
- 筛选在数据库分页前执行，总数、预警统计及两类导出使用相同条件与权限。导出覆盖全部匹配记录，不只导出当前页。
- 修改筛选、输入关键词或点击“只看我的店铺”只修改草稿，点击“查询”才应用。首次进入、翻页、调整每页条数和刷新仍加载数据，翻页、刷新及导出沿用上次已查询的条件；切回浏览器标签页不自动请求。重置清空并重新查询。
- 多选按商品明细 ID 跨页保留，可跨页批量分配渠道、修改运营订单状态、复制物流单号；重新查询、重置、刷新或操作成功后清空，避免误操作旧结果。WFS 不可勾选，批量操作仍由后端校验权限、版本和数量上限。
- 列名统一为“采购状态”。采购成功时间、采购分配时间在列表和完整导出中仅显示北京时间日期（YYYY-MM-DD）；后台保留精确时间用于小时提醒与时间区间筛选。
- 表头设置支持勾选显示列、拖动手柄排序；靠近列表边缘时自动滚动。店铺名、订单号保持固定左侧，不参与拖动。保存后写入当前账号的 `orderTablePreferences`，刷新、重新登录和换电脑可恢复；取消不保存，保存失败保留草稿以便重试。
- 首次没有服务端配置时兼容同账号的旧浏览器勾选设置，保存后以数据库为准。列设置不改变任何订单数据，也不改变两类导出的固定列顺序。

## 审核与供应商分配状态

订单列表新增“审核状态”（`reviewStatus`）和“分配供应商状态”（`supplierAssignmentStatus`），可筛选、参与表头显示/拖动设置及完整订单导出。两字段由系统维护，不能人工编辑或映射导入；采购填写模板的 14 列保持不变。

| 是否可分配 | 采购渠道 | 审核状态          | 分配供应商状态    |
| ---------- | -------- | ----------------- | ----------------- |
| 空值       | 任意     | 未审核（存 NULL） | 未分配（存 NULL） |
| 是         | 空值     | 已审核            | 未分配（存 NULL） |
| 是         | 有值     | 已审核            | 已分配            |
| 否         | 任意     | 不可分配          | 不可分配          |

编辑或采购导入变更是否可分配、编辑或分配操作变更采购渠道时，在同一事务中重新计算两状态。是否可分配为空或否时禁止新增、替换采购渠道，后端同时校验单条、批量及直接编辑请求；任一批量目标不满足条件则整批回滚。允许清空渠道，也允许将是否可分配清空。清空是否可分配或改为否不会删除已有渠道，保留记录供核对，但显示状态按上表处理。

采购导入空白单元格继续保留原值；需要清空是否可分配时使用编辑页面。WFS 人工只读和运营店铺权限继续生效，筛选不能扩大权限，两类导出与列表使用相同状态筛选。

Walmart 新建订单的是否可分配、采购渠道及两个新状态均为空；重复同步不清空人工数据。增量迁移添加两个可空列，每批 500 条按历史是否可分配和采购渠道回填状态，不改原采购值；可重复执行。部署前必须执行统一的 `npm run db:migrate`，不需要 Redis 或消息队列。

## 采购分配时间

`purchaseAssignedAt` 为系统自动记录的采购分配时间。单条分配、批量分配或编辑使采购渠道实际变化时，在同一事务内更新为服务器当前时间，清空渠道也记录；重复保存相同渠道或仅改变多选顺序不更新时间。仅修改是否可分配、采购导入及 Walmart 重复同步不重置此时间。该字段不能手工修改或映射导入。

历史数据保持空值，不根据旧采购人员分配时间推测回填。订单列表在采购渠道后显示该列，可通过表头设置排序和隐藏，完整订单导出包含该列。采购分配日期使用与平台发货日期一致的区间选择框，按北京时间开始日 00:00:00 至结束日 23:59:59（包含该秒全部毫秒）筛选；选择后点击查询才生效，清空或重置解除日期限制。列表、统计及两类导出共用条件和权限，采购填写模板列不变。

增量迁移仅增加可空 `DATETIME(3)` 字段及时间筛选索引，可重复执行；不需要新增缓存或队列。

订单列表底部展示“今日分配”渠道汇总，替代原订单来源说明。按北京时间当天最新采购分配时间和当前采购渠道统计商品明细，多选渠道各计一条；不按订单号去重，不累计历史分配操作，改分归入新渠道、清空不计入。历史分配时间为空的明细不计入。

统计独立于列表筛选和分页，但遵守运营所属店铺权限。随列表查询、翻页、刷新及分配完成后的刷新更新，不额外轮询；北京时间午夜自动隐藏昨日数字，新查询返回当天数据，不删除任何业务记录。数据库使用分配时间范围及现有索引先聚合渠道组合，只返回渠道计数，不下载全部订单。

## 采购成功时间与跟踪号提醒

`purchaseConfirmedAt` 为自动生成的采购成功时间，订单列表和完整订单导出可显示；不可人工编辑，也不可通过 Excel 映射导入。服务器在实际保存采购状态时应用以下规则，上传或预览不触发：

| 状态变化                                                       | 采购成功时间       |
| -------------------------------------------------------------- | ------------------ |
| 空值或其他非成功状态 → 采购成功未出跟踪号 / 采购成功已出跟踪号 | 记录当前服务器时间 |
| 两个成功状态之间切换，或重复保存同一成功状态                   | 保留原时间         |
| 成功状态 → 采购中、采购失败、取消订单、砍单等非成功状态        | 清空               |
| 未提供采购状态，或无效采购状态被导入跳过                       | 不改变             |

成功状态识别兼容空格及中英文括号。“采购成功（砍单）”属于非成功状态。普通编辑和采购导入共用规则；若成功状态历史记录原时间为空，成功状态之间切换也不会凭空补一个时间。

未出跟踪号提醒按服务器时间连续计时，包含夜间和周末：不足 24 小时普通提醒，24 至不足 48 小时黄色，满 48 小时红色“强制处理”。填写物流单号隐藏提醒，删除后按原采购成功时间继续计算；关闭页面或重启服务不重置。

增量迁移为缺少该字段的表添加可空列，并仅为已有“采购成功未出跟踪号”且时间为空的记录以迁移时刻补齐，不倒推历史、不覆盖已有时间。

## 编辑与同步并发

编辑表单只提交实际修改的可编辑字段及打开时的原值。服务器在事务内比较这些字段的最新值：后台同步或其他账号只修改了无关字段时可以保存；同一字段已变化时返回具体字段名称并保留表单内容，不能自动覆盖。手工清空仍显式提交 NULL。未携带字段原值的旧客户端继续按整条记录版本校验。

Walmart 重复拉取相同业务值不增加订单版本；实际平台字段变化仍增加版本，以兼容旧客户端。商品快照抓取时间等内部信息不参与人工冲突判断。采购导入使用预览采购摘要校验，详见[采购导入](purchase-import.md)。该优化不新增数据库字段、依赖或队列。

## 升级

先执行 `npm run db:migrate`，再启动新版后端。迁移只新增表、字段和索引，不清空订单、采购或店铺数据。已有订单的地址指纹分批补齐；金额及履约方从保存的 Walmart 原始响应回填，缺少原始响应时保留原值，等待下次官方同步。回填不请求远端接口，也不触发订单确认。
