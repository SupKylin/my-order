# 采购统计汇总

## 入口与权限

- 菜单及路由：采购统计汇总 `/purchase-statistics`，查询接口 `GET /api/purchase-statistics`。
- 管理员、主管、采购查看全部店铺，运营只查看当前绑定账号的店铺。读取快照时再次应用店铺权限，调整店铺所属账号后立即生效；渠道选项也只来自可见快照。
- 页面只读，不提供手工新增、修改、删除或强制重算历史快照的接口。

## 每日采集

- 每天北京时间24点（次日00:00）聚合系统内截至采集时刻的累计采购情况。11月16日24点执行的报表标为11月16日。
- 按商品明细计数，不按商品数量、采购数量或客户订单号计数。排除WFS（含历史WFSFulfilled）和平台已取消明细；采购状态为取消采购与平台订单取消不同，不据此排除。
- 只读取现有本地数据库，不调用Walmart，不更改原订单/采购数据。数据库按店铺、采购渠道组合、采购状态先聚合，再归类保存，不拉取全量订单字段。
- 每期与各店铺渠道组合数据在一致性事务中提交，失败整体回滚；日期主键避免多个实例重复生成。历史快照不被后续状态、渠道、字典变更重算。
- 失败每分钟重试，显示实际采集时刻，延迟超过一分钟会标注。白天启动安排下一次零点；启动恰逢零点第一分钟可采集当期。停机期间缺失的历史日期不按恢复时状态倒推，页面只显示实际生成的快照。跨日严重延迟只采集最近一期，不生成缺失多日快照。
- 初次上线前不补历史；尚无快照显示明确提示与横杠，不能将未采集当作0。刷新仅读取已生成报表，不触发采集。

## 数量与比例

| 分类 | 采购状态 |
| --- | --- |
| 采购成功 | 采购成功（未出跟踪号）、采购成功（已出跟踪号）、采购成功（已发货无单号），复用现有成功判定 |
| 采购失败 | 采购失败、采购成功（砍单） |
| 采购中 | 采购中 |
| 其他 | 空值、取消采购及其他自定义状态 |

- 多渠道明细在每个渠道计1条，同一明细内重复渠道只计1次；整体按商品明细去重，因此各渠道相加可能大于整体。
- 总采购单数＝成功＋失败＋采购中＋其他。成功率、失败率、采购中占比分别除以对应范围的总采购单数，保留两位小数，总数为0时比例为0%。三项比例不保证合计100%，因为有其他状态。
- 整体汇总增加未分配采购单数及占比：采购渠道为空（NULL、空字符串、空数组或纯空白）的明细计未分配，未分配占比＝未分配÷整体总数。未分配可与各采购状态交叉，不是额外加在整体总数之外的一类。

## 页面与筛选

- 日期范围为快照统计日期，北京时间，默认最近30个已结束日期，单次最多366天。起止日期均包含在查询范围内；日期控件禁用北京时间今天及未来日期，选中起点后限制366天跨度，并提示“最晚可查询昨日（北京时间），今天的数据将在24点生成”。手工输入查询前校验，无效不请求且保留原查询结果；后端保留非法日期、未结束日期或反向范围的校验。共用范围规则见[日期控件](date-controls.md)。
- 采购渠道为可搜索多选下拉，同框内取并集，可查询已停用/改名后的历史渠道名称。修改日期或渠道只改草稿，点击查询生效；刷新和翻页沿用已查询条件；重置回到默认日期和全部渠道。
- 顶部整体汇总取所选日期范围内最新一期，独立于采购渠道筛选，保留未分配；不能将多天累计快照加总。
- 明细按统计日期倒序，同日按渠道总采购单数倒序，展示成功/失败/采购中/其他数量及三项占比、实际采集时间。服务端分页20/50/100条。表格横向滚动，页面允许纵向滚动。

## 存储与验证

- 增量迁移新增 `purchase_statistics_snapshots` 与 `purchase_statistics_groups`，索引为日期/店铺。已接入初始化及正式迁移脚本；重复迁移不覆盖快照，不修改原业务表。复用Node定时器、Sequelize和MySQL，无新框架、依赖或外部组件。
- 服务启动安排任务，停止时取消定时器并等待进行中的事务。统计报表不属于两个月操作日志清理范围。
- 单元验证：`node --test backend/test/purchase-statistics.test.js`。
- 集成测试仅允许 `DB_NAME=my_order_purchase_statistics_test_数字时间戳` 临时数据库，自动创建并清理该测试库；覆盖并发幂等、迁移、WFS/取消排除、权限、历史固定、整体去重、失败回滚、HTTP四角色鉴权。不要对业务库执行初始化或测试重置。
- 前端用模拟API验证四角色菜单、查询才应用、跨页条件、整体独立、失败/无快照展示及1366×768布局；不造真实历史数据。
