# 渠道变更工单

2026-11-25 本地实现，尚未发布。

## 入口与流程

- 订单管理操作列增加“采购渠道变更”。没有未关闭工单时打开创建弹框；已有未关闭工单时直接打开详情。订单号和展开详情显示工单标记，点击在订单页内打开详情，不丢失查询、分页、勾选或滚动位置；也可进入独立“渠道变更工单”菜单。
- 菜单页面采用紧凑列表布局，移除外层重复的大标题、英文说明和协作徽标，保留列表标题、条数与查询区。
- 按商品明细建立工单，每条明细最多一个未关闭工单。关闭后可重新申请；历史记录保留。重开历史工单时，若同一明细已有其他未关闭工单，拒绝重开。
- 创建页展示当前商品信息及采购信息、变更前采购渠道，创建时任何角色均不能选择或提交目标渠道。工单进入列表后，仅管理员、采购可在详情选择已启用采购渠道（支持多选），确认时不能与当前渠道相同。创建只保存申请，不修改订单。采购商品链接、采购Sku、采购商品链接金额、采购平台、发货模式、采购商家名回填现值并可修改或清空；采购限价继续按链接金额×1.1自动计算，不能手填。详情可展开对比申请前与申请值。
- 详情显示申请时的原渠道、目标渠道，以及订单当前采购信息。文字、最多20张图片和粘贴上传沿用采购售后；记录按时间展示发送人，发送后不可修改或删除。打开、手动刷新、提交成功时更新，不定时轮询。
- 仅管理员、采购可点击“确认变更”，主管和运营禁止选择渠道及执行。后端重新校验渠道字典、是否可分配为是及原渠道仍与申请一致；不一致时提示关闭旧工单、重新申请，不覆盖他人的新渠道。新申请同时校验上述六项采购信息与原值一致，重新校验实际变更的平台/模式等字典值；未修改的历史停用值允许保留。
- 确认后在同一事务中更新采购渠道、申请实际修改的采购字段、采购限价/价格系数、采购分配时间、派生分配状态、订单版本，并将采购状态及采购成功时间清空；订单页同步刷新底部今日分配计数，以及执行人、执行时间和不可变事件记录。已结算订单修改发货模式时复用既有FBA/FBM成本规则，所需成本渠道或折扣缺失则整笔不执行，结算佣金不重新抓取。重复确认或网络重试不再更新订单。关闭、重开仅影响工单，不自动执行或撤销渠道变更；已经执行的工单重开后也不会重复执行。

## 权限与通知

四角色均可创建、回复、关闭、重开。管理员、主管、采购访问全部店铺；运营仅本人所属店铺；主管和运营不能确认变更。订单管理单条、批量及编辑分配渠道也仅管理员和采购开放；采购状态修改仍向主管开放。采购备注和跟单备注仅管理员、采购可修改，覆盖编辑、批量覆盖/追加/清空和后端接口。运营和主管Excel导入忽略这两项并提示，旧预览提交同样校验，其余有权限字段继续导入。WFS订单不能创建或写入工单。权限同时覆盖菜单、API及事务内校验。

创建和回复推送渠道变更专用企业微信群（`WECOM_CHANNEL_CHANGE_WEBHOOK`），采购售后继续使用原 `WECOM_AFTER_SALES_WEBHOOK` 群，不@人员，沿用完整内容与多图合并消息、长消息分段、工单链接及失败重试。通知包含当前渠道、申请时原渠道和目标渠道，不展示采购状态。关闭、重开和确认变更不额外推送。通知内容在提交时保存快照，重试不读取后来修改的渠道。

复用现有企业微信队列及每4秒最多一段的限速，不增加框架、外部组件或独立发送循环。测试使用模拟传输，不发送真实测试群消息。

## 数据与接口

- 新增 `channel_change_tickets`、`channel_change_records`；记录表没有修改/删除接口，也不随操作日志的两个月清理而删除。
- 工单增加可空JSON字段 `beforePurchase`、`targetPurchase` 保存原值和申请值，`executedBefore`、`executedAfter` 保存确认时实际采购信息全量快照。旧工单不推测补齐历史值。迁移可重复执行，本地已完成增量升级。
- `openItemId` 为可空唯一键，未关闭工单填商品ID，关闭后为NULL；配合商品行锁限制并发创建/重开。创建请求及回复使用幂等请求标识，关闭/重开/确认有工单版本检查。
- 现有通知表新增可空唯一 `channelChangeRecordId`，原 `recordId` 改为可空并保留唯一索引。采购售后和渠道变更记录分别占各自标识，编号相同也不冲突；既有通知保留。
- 迁移 `backend/src/migrations/channel-change-tickets.js` 已接入标准 `db:migrate` 与初始化流程；只建新表和增量调整通知列，不回填、删除或修改历史业务订单。
- 订单列表/详情批量读取工单标记，优先显示未关闭工单，否则显示最新一条历史工单；不把一对多工单关联加入订单分页或统计JOIN，避免重复条数。
- API 前缀 `/api/channel-change-tickets`：GET列表、POST创建、POST `/export`按已查询条件导出、GET `/:id`（记录每页50条）、POST `/:id/records`回复、POST `/:id/status`关闭/重开、POST `/:id/apply`确认变更。
- 菜单列表支持关键词、工单状态、店铺可搜索多选、店铺所属账号、当前采购渠道多选（含未分配）、采购状态多选（含未填写）和创建日期范围。日期按北京时间，包含起止当天，最晚今天；前后端校验非法、颠倒及未来日期。点击查询才应用条件，刷新和翻页沿用已查询条件；处理中计数跟随全部其他条件，跨分页且独立于工单状态筛选。店铺与账号选项及查询均遵守运营本人店铺权限。

## 批量分配与底部计数

- 列表新增“批量分配采购渠道”，复用订单管理的渠道多选弹框。仅管理员、采购可用；跨页勾选1至500条“处理中且未确认变更”的非WFS工单，显示已选条数。查询、重置、手动刷新和变更成功后清空勾选；翻页保留，返回页使用最新版本并剔除已关闭/已执行工单。
- 批量分配直接批量确认变更，同时写回各工单申请的采购信息、清空采购状态与原采购成功时间、更新分配时间，分别保存实际前后快照和执行记录。复用单条确认逻辑，在同一事务按商品ID顺序锁定；任一版本冲突、渠道/采购信息变化、不可分配、WFS、关闭或已执行均整批回滚。失败保留选择和弹框输入。
- API新增POST `/api/channel-change-tickets/batch-apply`，参数为`items: [{id, version}]`及`targetChannels`。拒绝重复、超量或无权限请求，不因重试重复执行。
- 底部“今日分配”直接复用订单管理组件和 `/api/orders/purchase-assignment-summary`，统计北京时间当天全部有权限订单的最新分配时间＋当前渠道，**包含普通订单分配，不仅限工单**；独立于筛选和分页，多渠道分别计1条。进入、查询、翻页、刷新、单条及批量确认后更新；午夜隐藏昨日计数，不新增网络轮询。
- 本次追加验证：25项渠道变更集成＋1项角色权限测试全部通过，覆盖21条工单跨页选择、事务整体回滚、权限/WFS/版本/重复执行保护及包含普通分配的计数一致性；前端生产构建通过。未发布。

## 导出与历史

- 工单导出按已查询条件跨分页取得有权限的商品明细；“订单明细”作为第一页，复用订单管理完整字段，同一商品去重。
- 工单导出及订单管理完整导出均附加“渠道变更历史”表，每次已确认变更一行，记录工单号、商品身份、执行人、时间，以及确认时实际渠道、采购状态、采购信息等前后值。同一商品多次变更完整保留，不仅展示最后一次。
- 未确认申请不算已变更。旧工单缺少完整执行快照时，仅展示已有渠道记录并注明缺失，不用当前值冒充历史值。采购填写模板不加入历史表。
