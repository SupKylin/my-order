## 必须保留的业务边界

- 订单唯一来源为 Walmart API，按系统店铺名＋客户订单号＋Walmart SKU 匹配；订单号使用 `customerOrderId`，PO 仅用于平台调用和溯源。同步平台信息时保留人工采购信息。
- 接收起点为 2026-10-01 00:00:00 PST（固定 UTC−8），结束动态取本轮开始时间；每店约 20 分钟同步，最多并行 3 店。落库后再确认符合条件的 Created 订单；只读预览不确认。完整回查、重试规则见同步文档。
- 所有订单禁止人工新增、删除；WFS 订单人工只读，不能编辑、分配或采购导入。商品、规格、图片及收件信息由官方同步维护，规格不从标题推断。
- 商品数量为原 `quantity`，官方维护、只读；采购数量 `purchaseQuantity` 在新订单入库时初始化为商品数量，历史订单留空，之后可编辑和采购导入，重复同步不覆盖。列表和两类导出均保留这两个字段。
- 采购导入仅更新三项唯一匹配的已有明细；未匹配、重复、WFS、无权限行跳过并反馈。不更新采购渠道，空白保留原值。未匹配行的字段错误不阻塞其他有效行，已匹配行格式错误仍阻塞提交。
- 模板共享维护，只按去除首尾空格后的表头名称精确匹配，不依赖列号，不支持多个别名；不绑定渠道或工作表。工作表在每次上传时选择，模板支持复制。
- 分配对象为采购渠道，可多选覆盖。仅“是否可分配”为是时允许新增或替换渠道，允许清空；审核状态和供应商分配状态由系统计算。主管确认已停用。
- 管理员可访问全部；主管可访问除账号管理、采购渠道维护、采购状态维护外的所有菜单及全部店铺金额；采购可访问全部店铺订单但菜单受限；运营只能访问本人绑定店铺。数据权限覆盖列表、详情、统计、导出和导入。管理员、主管看全部日志及导入结果，采购、运营仅自己；导入仍由预览创建人提交。日志只读、保留最近两个自然月，不记录查看请求或内部 Walmart 同步。四角色完整矩阵见 permissions-audit.md。
- 采购状态修改、单条/批量采购渠道分配和售后供应商反馈向管理员、主管、采购开放，独立于维护字典权限；运营只读，按钮隐藏，服务端拒绝修改及清空。运营采购导入忽略采购状态并提示，仅状态行跳过，旧预览提交再次检查角色；共享模板保留映射。
- 修改筛选只改草稿，点击查询才应用；首次加载、翻页、刷新仍正常请求，使用已查询条件。导出覆盖所有符合条件的数据。表头选择和拖动顺序按账号保存，勾选支持跨页。
- 采购渠道筛选支持多选并集，可同时选择“未分配”；采购状态可跨页批量修改（最多 500 条），沿用成功时间规则，遇到 WFS、越权或版本冲突整批回滚。
- 跟单备注支持跨页批量覆盖、追加或明确清空（1至500条、12000字符）。追加按每条原备注换行拼接，原备注为空直接写入，任一条合并后超长则整批回滚；空白输入不能隐式清空。沿用账号店铺范围、WFS只读和版本校验，失败整批回滚；成功刷新并清空勾选，自动记录日志，不影响其他采购信息。
- 采购售后按每条商品明细一个独立工单，四个角色均有入口但沿用店铺数据权限，WFS不可创建或写入。内容＋多图沟通记录不可修改/删除，可售后完毕及重新打开，事件保留；原售后字段不自动生成工单。订单标识直达对应工单，详情分页，仅打开工单、手动刷新和写入成功后更新，不定时轮询，记录不随审计日志清理。见 purchase-after-sales.md。
- “是否采购售后”按关联工单自动回显，无工单否、有工单是，完毕后仍是；不可手改或导入。旧售后截图/结果/结果截图停用订单编辑、可选列和模板目标，保留历史数据库值及完整导出；旧映射和旧预览提交跳过并提示。订单筛选、统计按工单计算，状态标记可直达工单。
- 采购状态筛选支持“未填写（空值）”，匹配 NULL、空字符串及纯空白，与实际状态多选取并集，与其他筛选取交集；查询及两类导出一致，不向字典或订单写入空值选项。
- 风险地址支持六列表格模板与批量上传（每次 1000 条、10 MB）；只新增有效且唯一的地址，重复或错误行跳过并反馈，保留已有地址及备注。沿用管理员/运营权限和现有地址匹配规则，无需改写订单。
- 发货预警及其筛选仅针对平台“已确认”，截止时间为平台发货日期次日北京时间 15:00。采购成功、采购分配时间只显示日期，后台保留精确时间，两者系统维护、不可手改。

## 首页与店铺汇总的当前口径

- 采购渠道FBA／FBM两套参数，结算按发货模式保存折扣及成本；店铺佣金人工0至100百分比（≤2位），进入已结算时固定费率，后续店铺调费率不改旧单，退出结算清除、重结算取新费率。2026-11-09已发布利润新增扣除Walmart已退款金额（11月17日本地待发布版改为卖家退款净扣款）、加上工单已保存采购退款及手工争议成功金额；未结算、缺费率/成本、已退款缺金额或有工单未填退款均不计算，取消排除，支持负利润。周/月利润按PST原下单日期、周一至周日/自然月，沿用全局筛选、自有/三方分组和权限，三金额合计仅计已计算明细；未计算单列条数。原当月退款按实际退款发生日期不变。结算成本/费率已于11月7日发布，新退款利润口径已随20261109033018068-61205e发布。见 procurement-fields.md / home-dashboard.md。

- 首页 `/home` 为每日订单汇总；`/store-summary` 上方为店铺概况与绩效，下方为每日店铺订单统计，不重复放首页汇总。
- 订单统计进入页面或刷新时按数据库实时计算，最近 30 天包含今天；按固定 PST 自然日归组，不随夏令时切换。每日表日期倒序，同一天店铺按销售额倒序。
- 总订单数和 WFS 订单数按店铺＋客户订单号去重；审核、不可分配、采购状态等按商品明细计数。销售额为商品金额＋运费，不含税、不重复乘数量，排除取消商品行；Walmart funded 商品金额使用官方 originalPrice 单价×商品数量，不扣平台资助；普通 PRODUCT/SHIPPING 为行金额，不重复乘数量。退款改为店铺概况的“当月退款额”列和顶部汇总，每日表不再展示退款。当月退款改用/v3/returns，按固定PST本月1日至采集时刻的REFUND_COMPLETED时间归集，包含旧订单/旧退货本月退款、含税，不再用财务报表入账日期或含冲正净额。完成退款直接累计接口含税lineTotal，不再交叉核对整单金额或数量；缺金额/完成时间等异常行跳过并提示，其余有效行正常显示。尚未退款、发起中和取消状态不计入。每日采集，页面显示截至时间；跨月不沿用旧金额。
- 在线 SKU、八项卖家责任绩效及财务数据仍每日 PST 00:00 采集；页面刷新不直接请求 Walmart。平台失败保留并标明历史值。付款缺失回退最近成功缓存并标注原报表日期；官方有效 0 不回退，官方付款接口没有历史日期查询参数。待结算金额使用 closingBalance，非可提现余额；上期平台已支付金额取最近已结束对账账期的PaymentSummary/Total Payable，不再验证支付描述，展示账期起止和报表日期；不再把当期paidToYou改名当作上期付款。两项金额均按已查询店铺跨分页汇总，缺失不作零。
- 店铺汇总顶部全局日期（PST默认近30天含今天）、所属账号、店铺多选统一控制全部卡片和列表，点击查询生效、刷新沿用已查询条件，一次请求生成整页结果。自有/三方店铺各有一组概况卡片和列表，下方保留每日逐店统计，各表独立分页。订单指标按期间计算；平台绩效和财务仍按自身周期。店铺管理用三方开关维护，历史默认自有；标记不改店铺名称/订单键，在管理、订单、汇总及下拉显示。
- 订单列表底部“今日采购渠道分配汇总”仍按北京时间，当天最新分配时间＋当前渠道计明细，每渠道各计一条，遵守账号权限但独立于列表筛选。
