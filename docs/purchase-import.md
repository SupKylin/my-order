# 采购导入

前端订单 Excel 导入菜单、页面路由、空列表导入按钮和人工新增明细按钮已注释保留。原订单导入页面、后端接口和业务代码仍保留；这是前端入口调整，不是后端接口权限封禁。

采购模板必须映射系统店铺名（shopName）、客户订单号（orderNumber）、Walmart SKU（walmartSku）和至少一个采购字段。采购 SKU、采购渠道不参与目标定位。

- 三项唯一匹配已有商品明细：更新已映射且非空的采购字段，空白字段保留原值；不覆盖平台信息或采购人员。
- 三项未匹配、匹配到多个旧明细、店铺名或 Walmart SKU 为空：跳过，不新增订单或商品明细。
- 同批多行匹配同一个唯一目标：按文件上传区顺序及文件内行顺序更新，后面的非空字段生效。
- 原有数据格式错误仍需修正后提交；未匹配行不阻止其他正确行提交。
- 预览后目标被修改、删除或出现重复：提交返回冲突，要求重新预览，不改为新增。

预览、完成页及历史记录均提供完整跳过清单，包含文件名、Excel 行号、系统店铺名、客户订单号、Walmart SKU 和原因，前端每页 20 行。全未匹配时也可完成导入记录，更新数为 0。旧匹配规则生成的未提交采购预览必须重新生成。

验证：`node --test backend/test/import-matching.test.js backend/test/import-boundaries.test.js`。数据库集成测试文件为 `backend/test/purchase-import-integration.test.js`，只接受显式指定的 `my_order_purchase_test_数字时间戳` 临时数据库；自动创建并清理，不使用业务数据库。
