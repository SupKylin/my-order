# 角色权限与操作日志

## 权限范围

- 管理员：全部菜单、全部订单和全部日志。
- 采购：订单管理、导入采购、导入模板、操作日志、采购渠道/平台/状态维护；可查看和操作全部店铺订单。
- 运营：订单管理、导入采购、导入模板、操作日志、风险地址、运营订单状态维护；订单数据仅限店铺管理中 `ownerId` 为本人账号的店铺。
- 导入模板共享维护。采购、运营仅能查看自己的日志和导入结果。
- 店铺管理将一家店铺绑定到一个账号，一个账号可绑定多家店铺；运营的订单范围以此绑定为准。表头显示与拖动顺序独立保存到当前账号，不影响共享模板或其他账号配置。
- 既有 WFS 人工只读、禁止手工新增和删除订单、采购导入只更新唯一匹配订单等限制继续生效。

菜单过滤、路由守卫和后端接口白名单同时实施。运营的数据范围作为数据库查询的额外 AND 条件，覆盖列表、预警统计、详情、两类导出和所有人工写入。未绑定店铺、不存在的店铺及无所属店铺账号均不会回退到全量数据。账号角色每次请求读取数据库；店铺归属在写入事务中再次校验。

导入预览跳过其他店铺的行，反馈原文件中的店铺、订单号、SKU、行号及原因，不返回其他店铺的数据库明细。提交时重新校验店铺归属，已失去权限的行继续跳过。预览和 Excel 检查仅允许上传者使用（管理员可查看检查结果）；管理员和原创建人可查看导入结果，提交仍须由原创建人完成。

## 日志与保留策略

操作日志沿用 `audit_logs` 表，记录账号主动发起的新增、修改、删除、导入、导出及登录等操作，包括账号、时间、请求结果和字段变化。修改日志与业务事务一同提交或回滚；操作请求摘要在响应结束时异步写入，写入失败会输出服务端错误日志。进程异常退出可能丢失尚未落库的请求摘要，已提交业务事务中的字段日志不受影响。

密码、密码摘要、Client ID、Client Secret、会话和令牌不保存明文。整份导入 JSON 和 Walmart 原始快照不复制到日志；字段长文本最多保留 12000 字符。旧日志无法追溯补齐此前未记录的字段值。

按北京时间回退两个自然月（月底取目标月最后一天），日志查询即时排除过期记录。服务启动和每小时自动清理，每批最多 1000 条、每轮最多 10 批，避免长事务；若历史积压超过一轮上限，后续轮次继续清理。保留当前月对应日、时分秒之后的最近两个月日志，并非按整月清空。

日志及导入结果界面只读，任何账号（包含管理员）均无日志增删改接口。导入报告、订单、图片和账号等业务记录不属于日志清理对象。导入提交只能在导入采购页面完成。

查询、查看详情、翻页、刷新及轮询均不再生成日志，失败的查看请求也不记录。Walmart 预览和同步（手动或定时）不生成请求或入库变更日志；账号主动修改同步开关配置仍属于配置修改，正常记录。已有历史查询和同步日志不主动删除，沿用两个月保留规则。同步状态与错误仍可在店铺同步结果中查看。

## 数据库与验证

运行 `npm run db:migrate` 增量添加日志时间/账号/操作索引、导入创建人时间索引和订单店铺日期索引；不重建或清空业务表。沿用 Express、Sequelize 和 MySQL，无新增 Redis、队列或 npm 依赖。

独立临时数据库验证：

```powershell
$env:DB_NAME = 'my_order_permissions_test_' + [DateTimeOffset]::UtcNow.ToUnixTimeMilliseconds()
node --test backend/test/permissions-audit-integration.test.js
Remove-Item Env:DB_NAME
```

测试只有数据库名匹配 `my_order_permissions_test_数字` 才执行，结束后仅删除该一次性数据库。已有业务库不参与测试。
