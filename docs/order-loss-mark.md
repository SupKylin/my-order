# 订单亏损标记

2026-11-25 17:07:40（北京时间）已发布，版本 `20261125090158219-971805`。数据库备份及校验、增量迁移、订单查询、前端资源和公网健康检查通过；线上订单及售后返回亏损标记字段正常。

- 以商品明细为单位保存人工亏损标记，默认未标记。订单管理与关联采购售后列表共用同一个值，标记后显示红色“亏损”标签并整行标红；取消后恢复原来的发货预警等样式。
- 两页均支持单条“标记亏损／取消亏损标记”及“批量标记亏损／批量取消亏损标记”。单次1至500条，跨页勾选，提交前确认影响条数；查询、重置、刷新及保存成功清空勾选，翻页保留并更新当前页的明细版本。
- 四角色均可操作，管理员、主管、采购沿用全部店铺范围，运营仅自己所属店铺；WFS只读。无售后工单的订单也可标记，已完毕工单可标记或取消，不改变工单状态。
- 只用于人工识别，不修改采购信息、佣金、成本、利润、退款或统计金额，不自动根据利润正负标记，也不发送企业微信通知。
- 两页操作共用 `POST /api/orders/batch-loss-mark`，参数 `{items: [{id, version}], isLoss: true/false}`。服务器校验角色、店铺、WFS、版本和重复编号，按商品ID排序加锁；任一失败整批回滚，不部分提交。未改变标记的行不增加版本。审计记录操作人及实际变更前后值。
- `order_items.isLoss` 为默认false的非空布尔列；增量迁移接入 `migrateOrderFields`，可重复执行。仅通过专用操作接口维护，通用编辑和采购导入不能写入；Walmart同步保留人工标记。
- 本地已执行字段增量迁移。6项隔离MySQL集成测试通过，覆盖四角色HTTP接口、旧表迁移、两个模块列表和详情一致、财务不变、21条批量、越权/WFS/冲突整体回滚及并发。生产构建通过，Playwright模拟数据验证单条/跨页标记与取消、跨菜单一致、查询清空选择、返回页保持选择及红色行样式，无页面异常。
