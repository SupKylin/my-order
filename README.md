# 订单协作台

1.本地部署的运营与采购管理系统。前端 Vue 3 / Element Plus / Pinia / Vue Router / Vite / Axios；后端 Node.js / Express / Sequelize；数据库 MySQL `my_order`。

## 本地运行

要求 Node.js 20.19+（建议与本机现有 Node 20.20.2 一致）、MySQL 8；数据库服务监听 `localhost:3306`。

开发时在项目根目录执行：

```sh
npm install
npm run dev
```

也可双击 `start-local.cmd`，后台启动两项服务。前端地址 `http://localhost:5173`，后端 `http://localhost:3000`。日志保存在 `logs/`；PowerShell 中运行 `./stop-local.ps1` 可停止由启动脚本启动的本项目进程。

首次账号保存在本机 `.local-access.txt` 中，登录后可以通过右上角修改密码。该文件和 `backend/.env` 已加入 Git 忽略。

新环境：复制 `backend/.env.example` 为 `backend/.env`，填写数据库、至少 32 字符的随机会话密钥和至少 8 字符的管理员密码，然后执行 `npm run db:init`。普通初始化只创建缺失的表，不清空已有数据。需要显式重置时才运行 `node backend/scripts/init-db.js --reset --confirm=my_order`，该命令会彻底清空 `my_order`，请勿在生产环境误用。日常启动不执行自动删表或变更表结构。

## 业务规则

- 导入优先按 **订单号＋采购渠道** 匹配商品明细，再按订单号匹配剩余的**无采购渠道旧明细**；店铺和 SKU 不参与匹配。一个订单可保留多条明细，分别分配采购。多选渠道按完整集合匹配，忽略顺序；已有渠道的明细不被其他渠道或未填写渠道的导入行覆盖。补全旧明细渠道时同步更新匹配键。
- 每条商品明细只有一条采购记录和一个当前采购人员；采购商家为该记录中的单一商家字段。采购限价和价格系数人工输入。
- 订单管理统一提供新增、导入、单条/批量采购分配、取消分配及人员筛选，不再单设采购分配页面；旧 `/allocation` 地址跳转至订单管理的待分配筛选。新增或导入新明细时，采购人员由服务端绑定当前登录账号，列表显示用户名；重复导入已有明细保留原采购人员，仍可手工重新分配。
- **导入仅更新已映射且非空的字段**，包括采购字段。空白单元格、只有空格的值、未映射字段和缺少的列保留原值。数字 `0` 与“否”是真实值，会更新。采购渠道有一个可选补全规则：模板绑定渠道时，Excel 已映射的非空渠道优先；空白、缺列或未映射时写入模板绑定渠道。
- SKU 为可选商品字段，可以不填写、不映射；同一订单和渠道再次导入时，即使 SKU 改变也更新原明细。没有出现在本次 Excel 中的其他渠道明细保持不变。系统编辑页面手动清空字段并保存则会清除值。
- 同一个文件内重复行全部保留。先为整批预留同订单同渠道的匹配，再按 Excel 出现顺序使用同订单下剩余的空渠道旧明细（ID 升序，即创建顺序）；每条旧明细只更新一次，多出的行新增，原有多出的明细保留。重复导入同一文件不会不断新增；调整文件中重复行的顺序会改变对应更新的目标。每条明细保留独立采购记录与采购人员，新增明细绑定当前账号。
- 一批数据存在任意错误时不能提交；提交在数据库事务内完成。预览后已有商品发生变化会要求重新预览；同一预览重复确认不会重复导入。
- 订单、时间、金额、商品和收件字段按商品明细保存快照，采购也关联到商品明细。修改一条明细的状态不会更改同订单其他渠道的明细。订单表仅维护订单号身份。订单金额可能在多条明细中重复，界面不直接累加成销售总额。
- 导入模板保存工作表名、表头行和列映射。列顺序改变时按同名表头重新定位，缺少可选列时保留原值并提示；缺少订单号必填列、出现无法消歧的同名列时拒绝导入。
- 映射编辑支持“新增映射”和逐行删除。上传时展示全部 Excel 表头；未选系统字段的表头仍保存在模板中，重新打开可继续配置，导入时跳过这些列。上传示例后可从 Excel 源列中选择；编辑已保存模板时可直接填写新列号和表头。每个生效源列和系统字段只能使用一次，保存前仅必须映射订单号，SKU 可选。自动识别存在多个候选来源时由用户手动指定，错误会提示具体映射行。
- 模板可选绑定采购渠道，不绑定时维持原有导入规则。绑定使用稳定 ID，渠道改名后新预览读取新名称；已停用的绑定渠道需要重新选择或清空。预览中展示最终采购渠道，非法的 Excel 非空渠道会报错，不自动替换成模板渠道。
- 侧栏提供采购渠道、订单状态、采购状态三个维护页面，支持新增、改名、排序、停用。停用项不再用于新选择；历史订单保留原名称，编辑其他字段时可原样保存。修改后当前页面立即刷新元数据，同浏览器其他标签通过通知刷新，其他用户的已打开页面在聚焦或 15 秒内同步。预览后字典发生变化时，提交会要求重新预览。
- 商品列表中的商品与收件信息默认折叠。详情页面可维护用户要求的全部 44 个业务字段。
- 运营、采购、总账号当前拥有相同业务权限；仍保留至少一个启用的总账号，避免无法管理系统。

## Excel 与图片

升级匹配规则时，迁移会允许 SKU 为空，并将订单 ID＋采购渠道集合摘要的唯一约束替换为普通索引，保留所有明细和采购记录。旧规则生成但尚未提交的导入预览需要重新生成。

支持 `.xlsx`（旧 `.xls` 请在 Excel 中另存为 `.xlsx`），支持不同工作表和 1–100 行范围内的表头。默认上限 50 MB / 10000 数据行，图片上限 15 MB。

采购金额和价格系数为字符串（最多 255 个字符），支持非数字内容，不做小数位数校验或金额格式化；税费、订单金额、采购商品链接金额和采购限价仍最多支持 20 位小数。Excel 高精度数据请使用文本单元格；Excel 数值本身已丢失的有效位无法恢复。

Excel 导入时，采购状态不在当前启用下拉选项中则跳过该字段，并在预览中提示；已有明细保留原采购状态，新明细该字段留空，其他字段照常校验和导入。手工编辑仍从下拉选项中选择状态。

订单采购渠道支持多选，Excel 中使用 `/` 分隔，重复渠道自动去重；名称本身带 `/` 时优先匹配完整渠道名称。模板仍只绑定一个渠道，Excel 非空渠道优先。历史渠道名称原样保留。“主管确认”支持“是”“否”“已确认”“不可分配”。

标准浮动嵌入图片按左上角锚点所在行、列关联。映射时须将图片列对应到商品图片或相关截图字段。包含 WPS `DISPIMG` 和 Microsoft 365 单元格富值图片的解析路径；各软件导出的具体版本仍须用实际样表验收，解析失败会显示行号，不静默当作成功。跨多行的大图、同单元格多图存在歧义：按左上角所在行读取，同一图片字段保留首张并给出提示。

图片统一解码校验并保存为 WebP，生成缩略图。数据库存储相对路径，上传接口同时返回 `url` 和 `thumbnailUrl`。文件位于 `backend/storage/images/`；原始 Excel 位于 `backend/storage/excel/`，原始文件不公开下载。图片 URL 可供前端直接渲染，不要求登录，符合公网图片地址的要求；地址含随机 UUID。当前只监听本机，公网访问需部署服务器或配置网络入口。

商品图片和截图不会因为覆盖记录而立即物理删除，避免并发编辑及历史引用失效；原始 Excel、预览和未关联图片目前也保留在本地磁盘，请按业务周期备份与清理。

订单号、SKU、电话、邮编、物流单号作为字符串；Excel 中已经丢失的超长数字精度无法恢复，请将这些列设为文本。常见全零数字格式可保留前导零。日期用真实 Excel 日期或 `YYYY-MM-DD`。无法计算的公式须先在 Excel 中计算并保存，系统不执行公式或宏。

## 登录与安全

- 服务端 MySQL 会话＋HttpOnly / SameSite Cookie；登录后固定有效 7 天，重新登录刷新期限。
- 密码使用随机盐 scrypt 摘要，前端不保存密码或数据库凭据。停用账号和重置密码使旧会话失效。
- 写接口验证请求来源、会话 CSRF token 和专用请求头；登录具有限速。
- Sequelize 参数化访问配合字段白名单、格式校验、唯一索引及事务；不将客户端字段直接拼接为 SQL。
- 角色目前不作业务功能限制，账号管理也是开放的，符合当前需求。后续若有跨团队隔离，需要新增真正的权限策略。

## 模块与代码规范

前后端独立存放。新增功能优先扩展所属业务模块，避免把业务判断集中到应用入口或页面模板中。

```text
backend/src/
  app.js                  Express 组装、静态资源和路由挂载
  routes/                 按业务拆分的 HTTP 入口
  middleware/             登录外的来源校验、CSRF、上传和统一异常处理
  services/               订单、分配、导入、用户和本地文件业务
  migrations.js           字典与模板渠道的增量升级（不清空业务表）
  lib/excel/              工作簿、单元格、XML 关系、嵌入图片和行提取
  models.js               Sequelize 模型、关联和对外明细序列化
  fields.js               44 个业务字段结构及首次安装的默认选项
  dictionaries.js         可维护字典类型与默认数据来源
  validation.js           字段白名单、值校验和模板校验
  auth.js                 密码摘要、会话持久化和登录拦截
frontend/src/
  api/                    按业务封装接口；http.js 集中处理 Axios 和 CSRF
  composables/            订单查询/分配、四阶段导入的状态和操作
  views/                  路由页面和组件组合
  components/             字段、映射、订单表格、预览及弹窗
  stores/                 Pinia 会话信息与字段元数据
  utils/                  不依赖网络层的展示格式化函数
  styles/                 按布局、表单、订单、导入和响应式拆分的样式
```

按需加载分三层：路由页面使用动态 `import()`；订单编辑、模板编辑、采购分配、改密及导入预览使用条件挂载的异步组件；Element Plus 组件、指令及样式通过 Vite 插件按使用情况引入。后端仅在处理 Excel 或图片时加载 ExcelJS 解析模块或 sharp。

API 模块负责请求地址和载荷；composable 负责页面状态；业务组件通过 props / emits 或 `v-model` 与页面交互。数据库写入、事务、版本冲突与去重保留在后端服务层。三个可维护字典保存在 `dictionary_options`，后端验证与 `/api/meta` 均读取数据库，前端表单不另造一份下拉常量。

旧版本升级时执行 `npm run db:migrate`，新增字典表、默认数据及模板的可空 `purchaseChannelId` 字段，将数值金额列扩展为 `DECIMAL(36,20)`、采购金额和价格系数转换为 `VARCHAR(255)`、订单采购渠道列扩展为 `TEXT`（兼容历史单选文本，新值存储 JSON 数组）。可重复执行，保留现有数据和字典选项。新环境 `npm run db:init` 已包含该步骤。升级后重启后端。字典维护接口为 `/api/dictionaries/:kind` 和 `/api/dictionaries/:kind/:id`，其中 `kind` 为 `purchaseChannel`、`orderStatus`、`purchaseStatus`。

关键业务约束、安全边界、字段清空语义、图片坐标和并发控制均在对应函数旁注释。普通变量采用含义明确的名称；注释说明规则或原因，避免逐行重复代码。

在 VS Code 中打开 **order-management 文件夹**，安装推荐的 **Prettier - Code formatter** 扩展后，项目设置会启用保存自动格式化。统一规则位于 `.prettierrc.json`，使用 2 空格缩进、单引号、分号、100 字符打印宽度和 LF 换行。`.editorconfig` 同步基础编辑约定。

```sh
npm run format        # 格式化源代码、配置与文档
npm run format:check  # 只检查格式，可用于提交前或 CI
```

依赖、构建结果、上传文件、日志及本地凭据均排除在格式化范围外。后续修改应保持最小范围，并先执行格式检查，再按影响范围执行构建和已有测试。

## 迁移阿里云

1. 备份并迁移 `my_order` 和整个 `backend/storage/`，保持两者一致；不要在新服务器执行清空重置命令。
2. 部署 Node / MySQL，设置生产 `.env`：`NODE_ENV=production`、新数据库凭据、随机 `SESSION_SECRET`、`PUBLIC_BASE_URL=https://实际域名`、`APP_ORIGIN=https://实际域名`、`COOKIE_SECURE=true`、`TRUST_PROXY=true`。
3. `npm ci` 后 `npm run build`，用进程管理器运行 `npm start`。Express 会托管 `frontend/dist`，生产无需暴露 Vite。
4. Nginx 用 HTTPS 反代 `127.0.0.1:3000`，转发 `Host`、`X-Forwarded-Proto`、`X-Forwarded-For`，将上传限额设为至少 `65m`，导入请求超时设为 `180s`。
5. 仅开放 80/443，数据库保持内网访问，验证公网图片地址、登录 Cookie 和文件备份。迁移后旧会话会因新密钥失效，用户重新登录即可。
